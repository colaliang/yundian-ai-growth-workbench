# 报告与小规模验证

报告结构：结论速览 → 企业产品与约束 → 候选发现证据 → 产品×市场×买家比较 → 可比价格/成本情景 → 评分及证据覆盖 → 风险/缺口 → 验证计划 → 下游交接 → 来源及局限。

候选表：opportunityId、产品/规格、国家、买家/场景、需求来源、差异化、可比报价、供应/准入、参考分、证据覆盖、缺失维度、推荐状态和淘汰理由。

验证单：假设、客户类型、待验证信号、任务/产物、渠道、预算待确认/已授权、时间窗、样本要求、负责人、成功标准、停止标准与依赖。无客户基线不默认承诺询盘量、成交率、CPL或翻倍增长。

验证顺序：确认产品及准入 → 草拟承接页面/内容与买家访谈问题 → 客户选择渠道并授权 → 实际询盘/样品/报价记录 → 背调确认匹配 → 销售反馈 → 决定补证、主推或淘汰。客户已有网站直接用现有承接条件，不强制重建。

Google/Facebook广告只做报告/建议，不执行测试投放；采购、上架、发布、发信需实际授权和工具。任务发出或网页存在不代表完成业务验证。

opportunities.json（可选）含schemaVersion、researchTaskId、cycleId、inputRefs及candidates。候选记录稳定id、productRef、brandId（已知才填）、market、buyerSegment、hypothesis、sourceRefs、scores、coverage、constraints、status、validationPlan、nextActions；缺失值明确null或待补。

下游交接：建站/内容使用已确认卖点与品牌规则，获客保留opportunityId，线索用leadId连接，背调记录产品/应用匹配，销售反馈记录联系、需求、样品、报价、订单、复购/退货及拒绝原因。确认的客户事实回写本地知识；市场假设单独保存版本，不覆盖企业技术事实。
