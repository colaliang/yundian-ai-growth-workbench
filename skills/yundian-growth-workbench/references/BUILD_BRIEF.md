# WorkBuddy 获客工作台 UI 与实现规格

定位：客户自主使用、定制获客流程的项目工作台，WorkBuddy 执行任务，知识库优先。固定七步主线：市场调研 → 产品机会 → 建站与内容 → 获客 → 客户背调 → 销售反馈 → 优化下一轮。默认不包含任何样例公司、数据、收入、线索或模拟成功状态。

首屏为项目关联与知识初始化：当前项目/实际工作目录、项目资料库/可选空间状态、上传或选择资料、定义目标。未完成显示需要处理的真实缺口。不要把本地目录当原生空间ID。

导航：增长总览、企业知识库、市场调研、产品机会、AI营销、客户背调、销售反馈、优化计划；工作流、产物与设置为辅助入口。主线固定，客户定制阶段子流程与渠道；AI营销为二级列表，包含建站、SEO/SEM/GEO、内容、Facebook/Ads只读诊断、主动开发、调研、产品机会、背调和质量复盘。

首页突出“今天推进哪一步获客工作”、下一步、待补资料、最近产物。使用原生 WorkBuddy 对话；没有经过验证的宿主调用接口时给可复制指令，明确需要客户在项目任务中运行。不得伪造原生连接成功。

采用用户提供云店+ logo、白底与低饱和灰、蓝色操作强调，避免大面积指标卡与多层悬浮菜单。宽屏单侧栏，窄屏折叠菜单；空态以用户真实操作引导。

项目数据位于授权目录的 `growth-workspace/`。初始化参见 `../scripts/init_workspace.py`；网页读写必须由受限本地文件服务完成，目录规范化后拒绝越界路径，写入使用临时文件+原子替换及版本冲突检测。不要覆盖客户的服务器或启动脚本。localStorage只可保存视图偏好。

WorkBuddy原生资料上传、归档及空间关联走实际宿主功能；无法调用时展示待关联与客户端操作路径。项目文件持久化、资料库索引和连接器授权是三个独立状态。

验收：空项目无假数据；初始化真实创建知识文件；重跑不覆盖；任务实际生成可读产物；刷新读取项目文件；修改冲突有反馈；外部失败不显示成功；客户能定制一个阶段工作流并关联上下游产物；能以 leadId 关联真实线索与反馈；未知成本与事实不显示确定数字。
