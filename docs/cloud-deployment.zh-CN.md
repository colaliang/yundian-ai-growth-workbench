# 腾讯云部署准备与本地迁移

当前 v0.15 工作台使用 Node.js 22.18+ 与 TypeScript。官方 HTTP、源码/编译 CLI 通过同一客户锁和持久事务写入，读取使用一致快照。Python submit_result.py 只委派同一 Node 回执入口；init_workspace.py 只支持未受管理的纯知识文件项目。server.py 保留为历史代码，不作为当前回退或受管理客户目录的写入入口，不与 Node 工作台同时操作同一客户目录。历史 Python 后端测试不是当前稳定性验收。Linux 新目录事务还需要构建并打包本项目的本机 no-replace helper，见当前部署文档。

## 本地迁移

1. 停止 Python 工作台，备份客户 growth-workspace 和 .codebuddy/skills。
2. npm start -- --root "客户实际目录" --port 8767。
3. 确认知识库、任务、产物和验收台账可以读回。无需导入或清空旧数据。浏览器刷新以获取新进程令牌。

## 云端部署门槛

当前文件版的互斥与恢复仅面向同宿主、本地文件系统，不代表分布式多客户云部署验收。PORT 可由环境变量配置；公网监听需显式 --public 或 WORKBENCH_PUBLIC=1，并配置所有者认证。私有配置位置可用 --private-base 指定，同一客户仍由 instanceId 隔离；HTTP 不能改选配置位置。准备云部署时核验以下事项：

- 存储适配：任务/流程/反馈/台账存数据库，附件和报告存对象存储；禁止依赖容器本地磁盘。
- 认证授权：验证用户身份，数据按 organizationId/workspaceId 隔离；每个读写操作检查权限。
- 并发：数据库事务或原子版本更新；文件版现有同宿主跨进程客户锁和多文件 journal 恢复，未知持有者身份或第三方字节变化时受阻；不宣称共享网络文件系统/集群互斥或断电保证。
- WorkBuddy 连接：客户本地连接层经认证领取任务、回传产物；云端不能直接读取客户电脑 I: 目录。
- 执行队列：持久化任务、幂等、重试与回写，不在 HTTP 请求结束后依赖临时后台进程。
- 容器配置：完成认证与存储后才开放 0.0.0.0，监听平台 PORT；/healthz 返回固定健康信息，日志不输出凭据或全量请求头。
- 部署确认：核验环境、访问范围、费用、存储与凭据注入，再执行实际部署。当前没有创建云资源。

短生命周期无状态 API 可优先 HTTP 云函数；将来需要 Agent 长连接、SSE 或自定义运行环境时采用腾讯云托管。实现数据库和存储前不提供可误认为生产就绪的部署按钮。
