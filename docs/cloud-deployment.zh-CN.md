# 腾讯云部署准备与本地迁移

当前 v0.12 是 Node.js + TypeScript 本地工作台，运行要求 Node.js 22.18+，无运行时第三方依赖。技能中的 Python 辅助脚本继续保留。server.py 暂时用于回退；不要同时运行两种后端写入同一目录。

## 本地迁移

1. 停止 Python 工作台，备份客户 growth-workspace 和 .codebuddy/skills。
2. npm start -- --root "客户实际目录" --port 8767。
3. 确认知识库、任务、产物和验收台账可以读回。无需导入或清空旧数据。浏览器刷新以获取新进程令牌。

## 云端部署门槛

当前文件存储和本机令牌不能直接提供公网多客户服务。HOST=0.0.0.0 会明确拒绝启动，防止误部署。PORT 可由环境变量配置。准备部署时完成以下改造：

- 存储适配：任务/流程/反馈/台账存数据库，附件和报告存对象存储；禁止依赖容器本地磁盘。
- 认证授权：验证用户身份，数据按 organizationId/workspaceId 隔离；每个读写操作检查权限。
- 并发：数据库事务或原子版本更新；文件版仅保证单进程内串行写入和单文件原子替换，不是多文件事务。
- WorkBuddy 连接：客户本地连接层经认证领取任务、回传产物；云端不能直接读取客户电脑 I: 目录。
- 执行队列：持久化任务、幂等、重试与回写，不在 HTTP 请求结束后依赖临时后台进程。
- 容器配置：完成认证与存储后才开放 0.0.0.0，监听平台 PORT；/healthz 返回固定健康信息，日志不输出凭据或全量请求头。
- 部署确认：核验环境、访问范围、费用、存储与凭据注入，再执行实际部署。当前没有创建云资源。

短生命周期无状态 API 可优先 HTTP 云函数；将来需要 Agent 长连接、SSE 或自定义运行环境时采用腾讯云托管。实现数据库和存储前不提供可误认为生产就绪的部署按钮。
