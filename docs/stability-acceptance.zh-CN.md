## 升级预检与回滚

1. 获取实际客户升级授权后，先只读核对应用版本、客户根目录、workspaceId、instanceId、锁状态和文件系统能力；不要复制私有目录或 session，检查 Linux 原子目录辅助程序已成功构建。共享盘/多机仍需独立验证。
2. 停止该实例写入，保留旧应用、客户目录与私有配置的独立受控副本；用旧版本和新版本分别检查资料数量与文件哈希。客户自定义技能与 registry 差异逐项比较，安装到独立官方版本目录，禁止覆盖客户技能。
3. 在独立目的目录预览并确认完整 bundle 恢复；核对 manifest、blob、MD/二进制、旧确认、SEO/GEO、成员及不可变发布 payload。目的实例身份保留，不复制凭据。错误 scope/损坏 bundle 必须零业务变更。
4. 实际升级前另行完成目标宿主与用户验收。若失败，保留新目录与事务日志证据，停止写入并切回保留的旧应用和升级前副本；不要把旧程序直接指向已升级的工作目录。恢复预览重新核对 fingerprint，禁止自动重试发布或自动删除未知备份。

E2 命令、日志、截图与审查报告保存在本地 .superpowers/sdd/2026-10-13-e-stability-delivery-plan/；整分支审查与最后修复证据位于 .superpowers/sdd/2026-10-13-workbench-stability-implementation-plan/。这些目录为 Git 忽略的本地证据，不表示已发布。
