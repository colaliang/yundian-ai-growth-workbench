# Linux atomic directory installation

New transaction directories on Linux require the packaged `native/bin/rename-directory-noreplace` executable. Build it on the target architecture/libc during development or image build using `npm run build:native` (also called by `npm run build`). This requires `cc` and Linux libc/kernel headers. There is no new npm dependency and no runtime compilation. Windows skips this build and retains its existing no-replace rename behavior.

The executable directly calls `renameat2(..., RENAME_NOREPLACE)`. Exit 17 means existing target; 69 means unsupported kernel/filesystem; other failure or a bounded 5-second timeout blocks installation. There is no check-plus-rename, copy, shell command or `mv` fallback. The adapter locates the binary relative to its own project module, passes literal absolute argv, and does not consult customer cwd or executable PATH. Keep the project code/native directory trusted and read-only to customers, like all application code.

Before a new-directory transaction is marked prepared, a private journal-local probe checks both rejection of an existing empty directory and successful identity-preserving installation. Missing binary or unsupported filesystem fails before business writes. Directory ownership, root-bound paths, staged files and journal recovery retain their existing checks. A capability flag identifies an implemented platform; the per-transaction probe establishes actual support. This is same-host/local-filesystem process-termination recovery, not a power-loss or network/distributed filesystem guarantee.

Packaging must include the native source, build script, and the architecture-matching executable alongside `src`, including compiled releases. Do not reuse Windows outputs as Linux binaries. For a Debian/Ubuntu Node image: install `build-essential` only in a build stage, copy the project, run `npm ci` and `npm run build`, then copy the application including `native/bin/rename-directory-noreplace` into a matching Node runtime stage. Retain executable mode 0755; runtime needs libc but no compiler. No existing Dockerfile is present in this checkout, so no deployment file was invented or deployment performed.

Primary reference: https://man7.org/linux/man-pages/man2/renameat2.2.html (RENAME_NOREPLACE, EEXIST, EINVAL, filesystem support). Actual Linux evidence and explicit validation gaps are recorded in `.superpowers/sdd/2026-10-13-b-write-recovery-plan/task-2-portability-report.md`.

Helper lifetime: Linux PR_SET_PDEATHSIG(SIGKILL) plus an expected parent PID check prevents a helper starting or lingering after its invoking Node dies. The caller also uses a bounded timeout. Recovery still verifies persisted directory identities after any completed atomic syscall.
