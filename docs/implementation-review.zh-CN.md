# 工作台与技能实现核对（2026-10-04）

## 结论

十个功能技能均已注册，网页业务阶段与技能映射一致。本地数据管理和验收机制可运行；AI研究、生成和外部渠道执行由WorkBuddy宿主承担，不是内置Agent后台。此次补充统一CLI和Node产物回写，减少对人工网页录入和Python回写的依赖。

| 模块 | 已实现的本地功能 | 仍需宿主执行/配置 |
|---|---|---|
| 企业知识库 | 初始化、资料/来源存储、索引、主体/品牌等文件 | 文件内容理解、原生空间绑定、ima/乐享查询 |
| 市场调研 | 实际记录、任务、报告保存与验收 | 实时搜索、贸易/竞争数据采集与判断 |
| 产品机会 | 产品机会记录、机会ID、任务及报告 | 需求/成本证据、评分和验证分析 |
| 建站 | 三平台任务路由、站点资料和代码交付记录 | 平台开发、部署权限与实际上线验证 |
| SEO与GEO | 38/26项台账、证据门槛、整改与复查字段 | 真实网站检查、统计/搜索后台授权与修复 |
| 内容运营 | 内容记录、选题/制作/发布计划任务 | 真实生成、发布工具、公开URL与效果读取 |

| 客户背调 | 主体/来源/判断记录与产物 | 真实来源查询、主体匹配与风险判断 |
| 销售反馈 | 实际线索反馈存储、轮次/原因/下一步 | 客户销售事实、CRM授权与结果读取 |
| 下一轮优化 | 反馈查看、优化资料和任务保存 | 按证据复盘、提出并创建后续任务 |

## 本轮新增

- scripts/workbench.mjs：state/save接口直接复用FileWorkspace；所有已有保存动作可由WorkBuddy调用。
- 技能主包中的scripts/submit_result.mjs：独立Node脚本，校验客户目录和任务ID，保存真实文件并读回；受阻可回写blocked/needs-input；不自动验收。
- 网页指令和技能统一改为Node回写，旧Python脚本继续兼容。

## 优先扩展方向

1. 结构化交接：任务显式关联recordId、opportunityId、leadId、上下游任务；目前主要通过输入文本及业务记录关联，尚无完整关联视图。
2. 可配置工作流：条件、依赖、重试和定时运行；当前步骤为客户定义文本，未提供自动调度引擎。
3. 可验证连接器：先读后写接入统计、CRM与知识来源，记录真实授权状态和回执；不能由技能说明推断API已接入。
4. 云端协作：存储、登录、空间隔离、跨设备与本地连接层，再实现腾讯云部署。

文件版CLI与网页仅单进程内分别保证串行写入；跨进程不存在统一文件锁。WorkBuddy应串行操作并在网页刷新状态，可通过--revision传入预期版本。多客户并发和事务应由下一阶段数据库版解决。
