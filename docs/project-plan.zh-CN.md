# 云店+AI增长系统项目规划方案 · WorkBuddy 获客工作台简化版

版本：v0.3，2026-10-03。替代简化版的顾问本机与演示定位；完整平台战略仍以完整规划为准。

## 1. 产品定位

面向跨境 B2B 外贸工厂与跨境卖家、由客户自主使用的 WorkBuddy 专用获客工作台。所有客户遵循同一获客主线，客户按自身情况定制市场、产品、渠道、步骤、工具与验收标准。云店+提供工作台代码和技能包，简化版直接利用 WorkBuddy 执行真实任务，产物保存在客户项目中。

工作台固定核心闭环：市场调研 → 产品机会 → 建站与内容 → 获客 → 客户背调 → 销售反馈 → 优化下一轮。长期保留自研云店+ AI Growth Agent 的战略，当前简化版直接利用 WorkBuddy 的执行能力。

## 2. 原生项目与知识库优先

一个客户业务对应一个 WorkBuddy 项目，项目共享指令、技能、连接器和资料。任务沿用原生对话；共享知识优先放入项目资料库，团队空间按客户实际权限关联。不要自行制造另一套登录、组织成员和聊天系统。

安装后首次调用技能必须初始化：

1. 选择或新建 WorkBuddy 项目，确认实际工作目录；避免写入技能安装目录。
2. 使用项目资料库；需要团队空间时在 WorkBuddy 中创建或选择实际空间，关联资料进入任务上下文。
3. 创建知识库索引、企业与品牌资料、产品服务、目标市场、客户画像、品牌规则和来源记录。客户已有资料优先导入，未知字段保留待补充。
4. 确认工作目标与约束，客户配置七步闭环中需要优先执行的任务与工作流；允许从已有业务阶段切入，不必先重新建站。
5. 完成首个真实任务，保存产物、证据与状态，回写知识索引。

技能导入不是自动执行钩子；首次对话触发上述流程。脚本只能创建本地真实文件，不能代替创建 WorkBuddy 云端项目或空间。原生操作缺少工具或权限时提供客户端操作路径，绑定保持“待关联”；本地文件存在不等于已进入原生 RAG。

官方依据：[项目及项目资产库](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project)、[资料库](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Library)。项目支持 `.codebuddy/skills/`；项目资产支持上传与任务产物归档。空间、项目、任务工作目录分别记录，不混用标识。

## 3. 工作台与 UI

首页首先展示当前项目、知识库就绪状态和“今天推进哪一步获客工作”。首次进入没有虚构数据，展示关联项目、创建知识库、添加资料、配置获客目标四步；知识不足时允许初始化和补资料，暂停依赖企业事实的业务输出。

导航建议：增长总览、企业知识库、市场调研、产品机会、AI营销、客户背调、销售反馈、优化计划；工作流、产物、连接器与设置为辅助入口。首页固定展示七步获客路径、当前阶段、下一任务与反馈缺口。客户可以调整渠道和子工作流，不将主线改成无边界的通用办公模块。AI营销二级菜单为 AI建站 / Shopify独立站 / WordPress定制建站、SEO/SEM/GEO、内容发布、Facebook、Google Ads、主动开发、市场调研、产品机会、客户背调与获客质量。

采用云店+ logo、浅色背景、单层主导航、克制蓝色强调。首页以目标、下一步和最近产物呈现，不铺满营销指标。对话使用 WorkBuddy 原生入口；网页提供可复制任务指令与文件定位，未验证深链接时不伪造“一键调用”。状态由真实文件或连接器读回，不由按钮模拟完成。

## 4. 可重复且可自定义的工作流

每个工作流保存：名称、版本、目标、输入来源、步骤、依赖、所需工具、产物格式、验收规则、预算、外部动作授权及反馈字段。客户自然语言定制后，先保存为可检查定义，再执行。

实际闭环：读取知识 → 检查缺口 → 建立任务记录 → 调用可用工具 → 保存产物与来源 → 验收 → 更新任务和知识索引。失败记录原因；只有实际产物可读且达到验收条件才标记完成。客户销售反馈区分有效线索、匹配原因、联系结果、报价、成交及拒绝原因；不能凭模型评分冒充成交质量。

七步核心能力必须保留，具体任务按客户选择执行：市场/竞品研究、潜在产品机会、SEO/GEO内容、建站需求、主动开发名单与草稿、广告只读诊断、客户背调、质量复盘。专家获客经验沉淀成版本化工作流，客户可以修改、复制和组合。

## 5. 真实运行架构

WorkBuddy 是任务执行宿主；技能是初始化、知识检索、定制和执行规范；项目文件是可读可迁移的持久化底座。`workspace.json` 保存客户配置；知识 Markdown、来源 CSV、工作流 JSON、任务 JSON 和产物文件保存实际工作。

本次技能包附带可运行的 Python 标准库初始化脚本：生成空白真实知识结构和配置，重复运行不覆盖已有内容。它不依赖模型密钥，不插入样例客户或模拟任务。后续任务由 WorkBuddy 读写这些文件并归档到原生资料库。

独立网页代码若要编辑配置/任务，必须通过限制在项目目录内的本地文件服务读写，包含原子写入、版本冲突检查和错误反馈。静态 HTML 可作为产物视图，但不能将 localStorage 当客户知识库或原生项目同步实现。浏览器令牌和供应商密钥不得写入配置。

外部工具按客户授权配置连接器。Apollo、Semrush、CRM、聚合沟通、乐享等分别标记未配置/已授权/已验证，显示实际成本或未知。当前广告仅官方 API 只读报告及官方后台跳转；不创建、修改或启停广告。发信、发布、采购按用户实际授权执行并保存回执。

## 6. 验收和落地顺序

P0：安装技能 → 原生项目选择 → 本地知识库创建 → 原生资料关联 → 客户定义目标 → 完成一个真实获客相关文件任务，并能沿七步主线保存输入、输出和下一步建议。验证目录隔离、重复初始化不覆盖、未知事实保持待确认、来源可追溯。

P1：实现上述 UI 与受限文件服务，刷新后数据来自实际项目文件；客户可调整每个获客阶段的渠道和子工作流，主线保持一致。验证故障不显示成功、任务结果能重新读取、已有资料不被覆盖。

P2：客户所需连接器和定时执行，逐项验证权限、回执、成本和反馈。自动化依赖宿主实际可用功能，不把工作流文件存在当成调度器已部署。

落地更新（2026-10-03）：本仓库工作台 已迁移为 v0.3 七步获客工作台，使用 server.py 将知识、任务、产物、验收和销售反馈保存到实际项目目录。WorkBuddy 通过原生对话和文件执行任务，页面刷新可读回产物。原生项目空间关联及外部供应商连接仍需宿主实际授权和验证。启动方法见仓库 README。

## 7. 七步闭环的输入、产物与反馈

| 阶段 | 核心输入 | 实际产物 | 下一步使用 |
|---|---|---|---|
| 市场调研 | 企业能力、市场范围、公开来源 | 需求/竞品/市场研究与证据 | 筛选产品机会 |
| 产品机会 | 市场证据、产品、成本和交付约束 | 机会清单、验证计划、卖点与目标客户 | 建站和内容定位 |
| 建站与内容 | 企业事实、机会、画像、品牌规范 | 站点方案、页面/内容、SEO/GEO计划 | 获客渠道承接 |
| 获客 | 目标市场、承接页面、渠道预算 | 渠道计划、实际线索/回执、广告只读报告 | 线索背调与分配 |
| 客户背调 | 真实线索和可追溯资料 | 主体、匹配程度、风险、跟进建议 | 销售跟进 |
| 销售反馈 | 实际联系、报价和成交记录 | 有效/无效原因与渠道质量反馈 | 优化依据 |
| 优化下一轮 | 前六步数据与销售反馈 | 有证据的改进假设、版本化下一轮任务 | 回到市场/产品/内容/渠道 |

任务记录应包含 cycleId、stage、上游产物引用及下游任务引用；线索和反馈使用稳定 leadId 关联来源、机会与渠道。不得为了凑齐流程虚构线索、成交或数据。缺少实际反馈时显示待反馈，优化建议明确属于假设。流程支持跳步和并行，例如已有网站直接做内容与渠道诊断；不是强制每客户从零重做。

知识库是七步共同的事实底座；执行记录与客户反馈持续回写。安装后先完成企业知识初始化，再选择当前阶段。真正完成一轮闭环需要实际线索及客户反馈，不能仅凭七份文档宣称获客闭环已验证。
